    03 · Two questions

    What It Buys. How It Pays.

    Live

    How it pays

    Caps per payment, per website and per day. A first-time recipient waits for a human. A price that changed after the quote is refused. Replays, bursts and wrong chains never reach the signer.

    Building

    What it buys

    Token facts read from the chain: can it still be minted, who holds the keys, is it a proxy, can it be paused or blacklisted. Facts only, never a score. Missing data means REVIEW, never ALLOW.

      06 · One call

      One Call, End to End

      01

      Ask

      The agent sends the payment request to the gate before it signs anything.

      02

      Answer

      The rules run and the gate says ALLOW, REVIEW or BLOCK, with the reason named.

      03

      Receipt

      The request and the answer are hashed together, so you can re-check them later.

      T+0.00  agent  ->  reinkeep   pay 0.90 USDG to 0x…dEaD
T+0.00  rules  ->  over_payment_cap
T+0.01  answer      BLOCK   id 8b79ded47376dc61
T+0.01  agent  <-  do not pay

      Step 3 of the scripted replay in the repository: a fetched web page told the agent to send 0.90 USDG to a stranger. It is a test scenario, not a live trade.
